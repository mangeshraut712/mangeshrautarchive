# Development safety

Local hardening, 2026-11-24. Coding agent: GPT-6 / Codex. Purpose: isolate tests, constrain cleanup, and enforce repository safety checks. Exact variant, reasoning mode, and token usage: unavailable.

## Highest blast radius first

1. **Production access from a developer account — manual action still required.** Rotate exposed credentials, move production access into a separate account this OS user cannot read, use repo-scoped credentials, and protect production environments. Local code cannot revoke existing access.
2. **Tests and development reaching production — repository controls added.** Use `npm run test:local` and `npm run dev`. Both filter inherited credentials, disable dotenv, restrict supported network clients to loopback, and use repo-local caches and temporary files. Remote database endpoints abort with a names-only warning. Production reads explicitly injected environment variables; it no longer autoloads local dotenv files.
3. **Destructive cleanup and remote schema changes — repository controls added.** `npm run clean` is a dry-run with resolved paths and file counts. `npm run clean:apply` deletes only listed generated directories after containment and symlink checks. Builds no longer delete a shared directory under `/tmp`. Worker deployment no longer automatically runs database migrations.

These are defense-in-depth controls, not an OS sandbox. Arbitrary subprocesses can still read files accessible to the OS user. Concurrent hostile filesystem changes can race path checks. Configure an actual project sandbox and separate production identities manually.

## Safe local commands

```sh
npm run test:local
npm run clean # no deletion
node scripts/utils/run-local.mjs npm run check
node scripts/utils/run-local.mjs npm run security-check
node scripts/utils/run-local.mjs npm run build
node scripts/utils/run-local.mjs npm run test:tester-army:ci
node scripts/deployment/deploy-status-worker.mjs --plan
```

No remote deployment, credentialed check, or account mutation is part of local verification. Host `HOME` is preserved; npm auth configuration is ignored and supported caches/temp files go under `.cache/local-runtime` (Linux uses the shorter repo-local `.tmp` for browser socket compatibility). Do not treat the command wrapper as safe for arbitrary unreviewed programs. The local network guard can be replaced by test mocks and does not constrain every possible native transport.

## Notification rollout (manual)

External contact notifications are **off by default**, including when the quota database is unavailable. Contact persistence remains a separate operation. Review and apply `scripts/integrations/notification-quota-schema.sql` manually using an appropriately scoped deployment identity. Set `CONTACT_NOTIFICATIONS_ENABLED`, `CONTACT_NOTIFICATION_ALLOWLIST`, and `CONTACT_NOTIFICATION_DAILY_LIMIT` in deployment settings, plus the existing provider configuration. The allowlist contains SHA-256 hashes of `channel:destination` (channels `telegram`, `discord`, or `webhook`), not raw destinations. Only the service role can reserve quota. Confirmed form submission and the chatbot's existing “send” confirmation set `confirmExternalNotification`; this flag is intent, not authentication. Failed sends conservatively consume the reservation. The SQL was statically reviewed; no remote migration was performed.

Production Worker workflows now accept a scoped `CLOUDFLARE_API_TOKEN` only. They no longer print credential prefixes or fall back to a global key. Destructive Vercel environment cleanup requires explicit credentials and a separate deletion confirmation; the automatic env synchronization/removal helper is retired. Remaining remote commands print their hazard and consequence before mutation.
